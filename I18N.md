# `@rhythm-archive/bms-player` — i18n Contract

Mirror of [`bms-editor/I18N.md`](../bms-editor/I18N.md). The player has a
smaller string surface (judgment labels, gauge state, HUD, runtime errors)
but the integration model is identical.

## Quick start

```tsx
import { I18nProvider, GamePlayer, type Translator } from '@rhythm-archive/bms-player';
import { useTranslation } from 'react-i18next';

function App() {
  const { t, i18n } = useTranslation('bms-player');
  const provider = useMemo(
    () => ({ t: t as Translator, locale: i18n.language }),
    [t, i18n.language],
  );
  return (
    <I18nProvider value={provider}>
      <GamePlayer /* ... */ />
    </I18nProvider>
  );
}
```

## Key surface

See [`src/i18n/defaults.ts`](./src/i18n/defaults.ts).

| Group         | Description                                     |
|---------------|-------------------------------------------------|
| `judgment.*`  | PGREAT / GREAT / GOOD / BAD / POOR / MISS / EARLY / LATE |
| `gauge.*`     | CLEARED / FAILED                                |
| `hud.*`       | BPM / Score / Combo / Accuracy                  |
| `errors.*`    | runtime audio errors                            |
| `state.*`     | game phase labels                               |

## Pass-through values

`#TITLE`, `#ARTIST`, keysound filenames, and chart metadata are user data —
the player never translates them.

## Without `<I18nProvider>`

`useI18n()` returns a translator backed by the English `defaultMessages`. The
player stays fully functional; only the labels stay in English.

## Versioning

Same as bms-editor: add = minor, remove/rename = major.
